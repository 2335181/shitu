# 拾图 开发维护文档

写给以后接手的人和 AI 编程助手。先读这一篇，再按需要读对应源码。产品需求以 `docs/开发规格.md` 为准。

## 1. 环境与构建

| 项 | 版本 |
|---|---|
| JDK | 21（`JAVA_HOME` 指向它） |
| Android Gradle Plugin | 9.x |
| Kotlin | 2.4.x，Compose + Material 3 Expressive |
| minSdk / targetSdk | 31 / 最新 |
| 原生库 | youtubedl-android（含 Python、yt-dlp、FFmpeg：libx264、libvpx-vp9、gif、libwebp） |

```bash
./gradlew :app:assembleDebug        # 调试包：app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:compileDebugKotlin   # 只检查能否编译，最快
```

- 调试包带 x86_64（方便在模拟器里跑 yt-dlp），正式包只打 arm64-v8a。
- 版本号在 `app/build.gradle.kts` 的 `versionName` / `versionCode`。
- 仓库地址 `GITHUB_REPO`（检查更新、查看源码会用到）也在 `app/build.gradle.kts`。
- **不要提交任何密钥。** SauceNAO Key、Gelbooru 凭证、Telegram Bot Token 都由用户在应用里填写，保存在本机 DataStore；Cookie 用 Android Keystore 加密保存。

## 3. 关键约定

### 3.1 网络
- 一律用 `Http.client`（带开发者日志拦截器）；Coil 加载图片用 `Http.imageClient`（不记日志）。
- 用 `call.await()`，不要在主线程同步 `execute()`。
- 面向用户的错误抛 `UserFacingException("一句人话")`；其他异常用 `friendlyMessage()` 转成中文。
- 可能拿到网页而不是 JSON 的接口（被拦截、要验证、需要代理），先判断首字符再解析，参考 `SearchEngines.parse()`。

### 3.2 开发者日志（`core/DevLog.kt`）
- `DevLog.warn(tag, msg)` / `DevLog.error(tag, msg, e)`，同时输出到 logcat 的 `ShituDev` 标签。
- 网络请求只记方法、域名、路径、状态码和耗时，**不记查询参数、请求头和 Cookie**。
- 「我的」→ 版本号连点 7 次开启开发者选项 → 查看和复制日志。

### 3.3 下载与保存
- 往队列里加任务：`container.downloadManager.enqueue(DownloadRequest(...))`。
- `DownloadSource` 有五种：`Direct` / `YtDlp` / `Ugoira` / `Sticker` / `Local`。新增来源时要做三件事：在 `DownloadModels.kt` 里加类型，在 `DownloadManager.run()` 的 `when` 里处理，需要原生能力的话照着 `UgoiraExecutor` 加一个执行器接口，再在 `AppContainer` 里接上。
- 默认保存位置：`Download/拾图/{图片|视频|音频|其他}/[subDir]`。用户也可以在「下载与存储」里换成任意文件夹（SAF）。
- 工具里直接生成的文件，用 `MediaSaver(context).saveFile(...)` 保存，会自动记进下载队列的「已完成」，点击即可用默认应用打开。

### 3.4 工具页
- 新增工具的步骤：
  1. 在 `ToolCatalog` 里加 ID 和 `ToolInfo`（`implemented = true`）；
  2. 写一个 `@Composable fun XxxTool(padding, header)`；
  3. 在 `WorkspaceScreen` 的 `when` 里加路由。
- 状态持久化：`rememberToolState(id, Serializer) { 默认值 }`，滚动位置用 `rememberToolListState(id)`。状态类必须是 `@Serializable`，**不要往里放 Token 或 Cookie**。
- 批量选择：在 `LazyColumn` **外面**调用 `RegisterSelection(count, total, onToggleAll, onDownload)`，导航栏上方就会出现全选和下载两个悬浮按钮，长按下载进入队列。列表里用 `SelectionCount` 显示已选数量。

### 3.5 设计
- 风格叫「纸与墨」：米白纸底配三团彩雾，标题用思源宋体，强调色是蓝色斜体。
- 组件在 `ui/design/Paper.kt`：`EditorialTitle`（`*文字*` 会渲染成强调色）、`Lede`、`PaperCard`、`MistCard`、`InkButton`、`SoftButton`、`SectionHeader`、`DotTags`。
- 颜色只用 `MaterialTheme.colorScheme` 和 `LocalShituPalette`，不要写死十六进制颜色。
- 动画用 `MaterialTheme.motionScheme`。
- 每次改界面都在模拟器上截图看一下。

## 4. 识图引擎接口（`feature/search/`）

```kotlin
enum class Engine(id, label, type: API|WEB, blurb)        // id 存在设置里，别随便改
suspend fun SearchEngines.run(engine, jpegBytes): EngineResult
sealed interface EngineResult { Loading; Hits(List<SearchHit>); Web(url); Failed(message, fallbackUrl) }
```

| 引擎 | 实现方式 | 中国大陆不开代理能否使用 |
|---|---|---|
| SauceNAO | 官方 API，需要 Key；结果被图站引擎共用 | 能 |
| trace.moe | 官方 API | 能 |
| IQDB | 解析网页。需要先领 `iqdb_bcc` Cookie；高峰期会排队几十秒（读超时设为 90 秒） | 能 |
| 百度识图 | 自带上传接口 `graph.baidu.com/upload`（需要 Referer 和 `Acs-Token` 头） | 能 |
| Google Lens / Bing / ascii2d / 搜狗 / TinEye | 先把图上传到 Yandex，拿到公开图片地址，再按网址搜图；Google 用 `uploadbyurl`，让用户自己的浏览器会话去上传 | 不能（Yandex 连不上） |
| Danbooru / Yande.re / Konachan / Gelbooru / Sankaku | 见下 | 能（取决于各站本身） |

**图站适配（`Booru.kt`）：**
- 召回：这几个站都不开放以图搜图（Danbooru 的 iqdb 接口要登录），所以用**同一张图只请求一次**的 IQDB 多站结果和 SauceNAO 结果做召回（`shared()` 缓存）。
- 识别：按帖子链接或 SauceNAO 字段（`danbooru_id` 等）认出是哪个站的帖子。Gelbooru 在 IQDB 里给的是 `md5=` 链接，也支持。
- 补全：再用各站公开 API 补标签、原图尺寸和分级：
  - Danbooru：`/posts/{id}.json`，必须用非浏览器 UA，否则会被拦到验证页；
  - Yande.re / Konachan：`/post.json?tags=id:{id}`；
  - Gelbooru：`dapi`，需要用户在「识图引擎」页填写 `&api_key=…&user_id=…`；
  - Sankaku：没有公开接口，只给链接。
- 新增一个图站：在 `Engine` 里加一项，在 `Booru` 里加正则、SauceNAO 字段和 `enrich` 分支，再在 `SearchEngines.HOME` 里加官网地址，最后把 ID 加进 `AppSettings.DEFAULT_ENGINES`（老用户的引擎列表由 `SettingsRepository` 里的迁移逻辑追加）。

## 5. 链接解析与直播流

- `LinkParser.parse(text, ytDlp, cookieFor)` 返回 `LinkResult(title, platform, media: List<LinkMedia>)`。各平台有专门解析器，认不出的平台交给 yt-dlp。
- 直播流（工具 ID 仍是 `douyin_live`，现在显示为「直播流」）：
  - **抖音** `DouyinLive`：先领访客 `ttwid`，再调 `webcast/room/web/enter`；分享短链按 room_id 走 `reflow/info`。
  - **B站** `BiliLive`：
    1. `room_init` 把短号换成真实房间号，同时拿到是否在播；
    2. `get_info` 取标题和封面，`Master/info` 取主播名；
    3. `getRoomPlayInfo` 按 `accept_qn` 逐档取 FLV 和 HLS 地址，只取 avc 编码。
  - B站未登录时最高只能拿到「超清」左右，登录后（会带上 CookieVault 里的 B站 Cookie）可以拿到原画。地址带时效签名。

## 6. B站收藏集
- `BiliGarbApi`：拿收藏集详情（`right/landing`）和表情（`item_emoji_list`，动态版在 `image_gif` / `image_webp`）；老表情包只给 `item_ids`，要逐个查 `suit/detail`。
- `BiliCatalog.rank`：搜索排序沿用 7.1.7 的计分规则——
  - 每命中一个字加 1 分；商城搜索结果每字 1.2 分；
  - 英文字母每个 0.5 分；
  - 关键词整词出现一次加 100 分；
  - 只取前 30 个。

## 8. 给 AI 助手的提示
- 先在本文档里找到对应模块，再读源码；不要整库重写。
- 用户可见的文字都用简体中文，不要用「请」「您」这类客套话，要说清楚下一步该做什么。
- 没有实际运行过的验证，不要说「已验证」。
- 提交前确认没有带上密钥、`local.properties`、`dist/` 和未打码的收款码原图。
